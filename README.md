# desk-tools: grade summary generator

Standard-library Python CLI scripts that turn a grade-management system's CSV export (one row per student per test date, one column per subject) into a per-student summary CSV: per-subject averages, a total average, the student's current Level, and a Status verdict (UP / STAY / DOWN / P, or PENDING) against configurable cutlines. Same-week duplicate entries are removed and reported. Two variants cover two class structures:

| Variant | Tracks | How the track is detected | Combined total for two-track students |
|---------|--------|---------------------------|----------------------------------------|
| `g1_5/` (grades 1-5) | MTW vs TFS | weekday code in the class name (`G3-21M(...)` vs `G3-21TH(...)`) | scores of both tracks pooled |
| `g6/` (grade 6) | E vs K | `[E]` prefix, or ASCII vs Korean teacher tag in the class name | E 60% + K 40% |

A Korean end-user manual for staff who do not program is in `docs/USAGE.ko.md` (English: `docs/USAGE.md`).

## Why I built it

While teaching at an English academy in Seoul I needed to turn the grade-management system's CSV export into a per-student summary with a level recommendation, quickly and repeatably, for staff who don't program. Every term the same steps were being done by hand in a spreadsheet: average each subject, weight participation, combine two tracks, compare with the cutlines, spot double-entered tests. I wrote these scripts independently on personal time so the whole thing became "put the CSV in the folder, run the script".

## What this is not

- **Not** official infrastructure of any school or academy, and **not** an assigned work product. It is a personal tool.
- Contains **no real student data**. Every CSV in this repository is synthetic and generated by `make_sample_data.py`; student names are `학생A` ... `학생O`, teacher tags are `TeacherA` / `교사A`, scores are random.
- The cutline numbers (`80 / 70 / 60`) are **placeholders**, not any institution's real thresholds.

## How the UP / STAY / DOWN verdict works (plain answer)

It is a fixed threshold rule, not a model. In each `generate_summary.py`:

- `get_target_level()` compares the student's total average to three hand-set cutline numbers (`LV_CUTLINES`) and returns level 2, 3, 4 or P.
- `get_status()` compares that target with the student's current level and returns **UP** if the target is a higher level, **STAY** if it is equal, and **DOWN** otherwise (a target of P is written as **P**). With `LEVELING = False` every status is **PENDING**.

There are no learned parameters and nothing is fitted. The optional `analyze_cutlines.py` proposes cutlines as a 70/30 blend of adjacent levels' medians (`0.7 * median(upper level) + 0.3 * median(lower level)`); that is a descriptive statistic the author chose, not a trained model.

## How to run

Python 3.9 or newer; no third-party packages.

```bash
# 1. (optional) regenerate the synthetic sample input CSVs
python3 make_sample_data.py

# 2. summarise -- reads CSV/ next to the script, writes next to the script
python3 g1_5/generate_summary.py
python3 g6/generate_summary.py

# other folders
python3 g1_5/generate_summary.py --csv-dir /path/to/exports --out-dir /path/to/output

# 3. (optional) propose cutlines from a summary
python3 analyze_cutlines.py g1_5/sample_grades_summary.csv
```

Outputs: `<input name>_summary.csv` per input file (g1_5) or one `<input name>_summary.csv` / `combined_summary.csv` (g6), plus `duplicate_entries.md` when same-week duplicates were found, and `cutline_report.md` from the analyzer. All three are gitignored.

Input format: a CSV with columns `반명` (class), `원생명` (student), `시험일` (date, `YYYY-MM-DD`) and any number of subject score columns. The subject list is read from the header, so nothing has to be edited when the curriculum changes. A column named `Particip` (configurable) is treated as participation and weighted separately.

## Settings

Edit the `SETTINGS` block at the top of each `generate_summary.py`.

| Setting | Default | Meaning |
|---------|---------|---------|
| `LEVELING` | `False` | Apply cutlines and write UP / STAY / DOWN. `False` writes PENDING for everyone. |
| `MIN_TESTS` | `5` | Minimum test dates per track; students with fewer are omitted. |
| `START_CUTOFF` | `None` | `datetime(...)`: students whose first score is on or after this date are excluded. `None` disables it. |
| `PARTICIP_WEIGHT` / `ACADEMIC_WEIGHT` | `0.1` / `0.9` | Weight of the participation column vs. the other subjects in the total. Set to `0` / `1.0` to ignore participation weighting. |
| `PARTICIP_COL` | `"Particip"` | Header of the participation column; if absent the total is just the academic average. |
| `JU2_WEIGHTS` (g6 only) | `{"E": 0.6, "K": 0.4}` | Track weights for students in both tracks. |
| `LV_CUTLINES` | `{2: 80, 3: 70, 4: 60}` per group | Placeholder thresholds; total average >= value gives that level, below Lv4 gives P. Separate sets for two-track students and each single track. |

Naming conventions the parsers rely on (only the shape matters; names are free text):

- Class: `G<grade>-<level><section><DAY>(<teacher>)`, e.g. `G3-21M(TeacherA)`. The digit after the dash is the class level. g1_5 reads the DAY code (M / TU / W = MTW, TH / F / SA = TFS); g6 reads `[E]` or whether the parenthesised tag is ASCII.
- Student name suffixes: `L3` (level override), `(P)` (below-Lv4 / probation marker), `주1` (once-a-week tag, stripped for display); g6 also `E2K3` / `K3E2` / `E3` / `K2` (per-track level).
- "주1 / 주2" in the output means enrolled in one track / both tracks (once / twice a week).

Averaging, for the record: g1_5 averages each subject (2 dp, round-half-up like Excel), takes the mean of the academic subject averages, and blends it with the participation average by the weights above. g6 pools all academic scores of a track, blends with participation, and then weights the E and K track totals 60/40 for two-track students.
